# Nodal core package (optional add-on): plan

Status (2026-10-07): **planned, not started.** Nothing here is built. Written after the deep dive on openndm (private survey notes, not in the repo)
and the decision that this is an **optional package** for users doing a PWR-type core, not part of the core app. A simple TRIGA or shielding user never sees it.

## What it is

An add-on component for OpenMC Studio that turns a lattice model into few-group constants (`openmc.mgxs.Library`), solves a coarse 3D core with
[openndm](https://github.com/rizkiokt/openndm) (MIT; C++17 core, Python API; eigenvalue, critical boron, rods, Doppler and moderator feedback, transient),
and shows the nodal k and power map **beside OpenMC's own k**. The first user is RAFT's BEAVRS PWR lesson, which needs fast boron, rod and feedback sweeps
that Monte Carlo cannot give.

## What the package is allowed to claim

openndm's own full-core comparison against OpenMC (its requirement "C-4") is **not started**. Until this package has run that comparison and shown it, the tab says
"fast estimate, checked against OpenMC on N cases" and shows the k difference in pcm beside every nodal result. No accuracy statement reaches a lesson before step P2 passes.

## What exists in Studio today (checked 2026-10-07)

- Rectangular and hexagonal lattice models and a RegularMesh tally with per-voxel mean and std in `results.json`.
- `provenance.json` records versions, nuclear-data hash, settings, seed, outcome. It does not yet record optional-component versions
  (`docs/plans/11` in the SEED repo says installed-component versions go in run provenance when relevant).
- No group-constant generation, no sweeps, no critical-boron search, no per-pin or per-assembly table.
- Optional components are planned by SEED (`experiment-studio/docs/plans/11-runtime-and-shared-acceptance.md`, "Optional add-ons"): each app publishes component
  IDs, versions, required/optional, dependencies, platforms, capabilities, hashes, sizes and licences. Nothing for it is built; the first add-on is CAD.

## Steps (each stops with a go/no-go)

**P0: can Studio make the group constants? (1 to 2 days, the first experiment.)** From a generated lattice test model (a small assembly array), build an
`openmc.mgxs.Library` with a chosen group structure and the lattice domains, run OpenMC to fill it, and load it into openndm in a throwaway script in the sandbox
(no repo change). Go/no-go: does it work with no extra user steps, and how long does it take on a small core? Output: a note with times and the manual steps found.

**P0 result (2026-10-07, done): GO for the group-constant path; the core-level accuracy is NOT there yet (+5.5 thousand pcm with a water reflector).** Script: [`nodal-p0/p0.py`](nodal-p0/p0.py) (throwaway; `nodal-p0/p0_adf.py` adds the factors and the reflective/vacuum variants; run in WSL in a venv
with `openndm 0.3.0` on top of the OpenMC 0.15.3 env; 4 threads). Test model: 5 x 5 pin assemblies (2.4 % and 3.1 % UO2, a guide tube, water), 2 energy groups split at 0.625 eV,
20,000 particles x 150 batches (30 inactive), constants tallied on the assembly universes (`openmc.mgxs.Library`, domain type `universe`).
- **Infinite assembly (the group-constant path alone):** OpenMC 1.30622 and 1.36311 (+/- 52 and 54 pcm); openndm on the same library, one node, all faces reflective: **-76 pcm and +9 pcm**.
  Inside the Monte Carlo noise. So Studio's lattice universes go through `openndm.gc.from_mgxs_library` with no translation code, and the domain order matches the lattice map.
- **8 x 8 core (6 x 6 checkerboard of the two assemblies, one water reflector ring, vacuum outside):** OpenMC 0.94469 (+/- 58 pcm); openndm **+5,470 pcm** (SANM, mesh-converged;
  +4,300 pcm for finite differences at one node per assembly). With a reflective outside instead: OpenMC 1.0795, openndm **+2,350 pcm** (SANM), and finite differences at two nodes per assembly
  within 730 pcm by luck of cancelling errors. A fuel-only 4 x 4 checkerboard with a reflective outside: **-8 pcm** (SANM): the fuel-to-fuel coupling is right.
  So the error sits at the fuel/water-reflector interface.
- **Discontinuity factors from the infinite lattices (openndm's `add_adf_tallies` / `compute_adf`, 0.995 to 1.013 for both assemblies) change the core k by less than 20 pcm.** They do not touch the
  reflector problem. The reflector needs its own treatment: factors from a fuel-plus-reflector configuration, or reflector constants from a fuel/reflector calculation. That is the first P2 experiment.
- **A correction to my first P0 note:** an earlier run of this experiment showed -7.9 thousand pcm. That was my set-up error: the water ring was also the lattice's `outer` universe, and openndm
  treats the outer universe as outside the core, so the reflector was silently missing. A model with the reflector as real lattice positions (not `outer`) gives the numbers above. The Studio wrapper
  must never use a physical region as `outer`, and should say so when the lattice has one.
- **Cost:** a nodal solve is milliseconds (5 to 120 ms); the OpenMC run for the constants is 80 to 100 s per case here (20,000 x 150, 4 threads, a machine with other agents on it). Group constants,
  not the solve, set the price. Timings are not clean (shared machine).
- **Manual steps found (the wrapper must do them):** `lib.legendre_order = 0` with `lib.correction = 'P0'` (with order 1 openndm's loader fails on the matrix shape: 8 values for a 2 x 2 x 2 matrix, a ValueError);
  the `openmc` executable must be on PATH (venv python and the conda env's bin on PATH); `openndm.gc.lattice_universes(lattice)` must be the library's domain list; the `outside` option of `from_openmc` is only for
  inactive lattice positions, the outer faces take `boundaries` (a first run with the wrong reading gave a nonsense k of 0.157, which would have looked like a solver bug).
- **Not done:** reflector-aware factors, two-step (single-assembly) group constants, 3D, rods, boron.

What this says:
- **The solver and the constants pipeline are not the main error.** With constants and factors from the core run itself the error is under 2.6k pcm for every slab width tried; without factors it is +5k. The discontinuity factors at the fuel/reflector face are what matter (fast 0.76 against 1.76 across the face, thermal 1.5 against 0.96).
- **A two-step recipe gets most of the way, with the opposite sign to the floor:** +1,980 to +2,510 pcm with the converged face flux. The oracle's floor is -2.6k to -3.2k, so the two-step error (about +5k against the oracle) and the method's floor (about -3k) partly cancel; the difference between E2 and E1 is what the strip misses that the core run has (the reflector spectrum behind a fuel checkerboard, the corner reflector nodes, which here reuse the edge constants). Do not read +2k as the accuracy of the method.
- **The face slab was a source of error of its own, now removed (E3, `nodal-p2/e3_face_flux.py`, K = 80).** A fixed slab reads a flux biased toward the node average, and the bias changes k by about 3k pcm between slabs of 1/80 and 1/5 of the pitch. The test that needs no k: the flux must be the same read from the two sides of an interface. Mismatch (rms, fast and thermal groups) at the fuel/reflector interfaces: slab 16/80: 30 and 43 %; 8/80: 17 and 29 %; 4/80: 8.7 and 16 %; 2/80: 4.2 and 8.0 %; 1/80: 2.2 and 3.8 %; **a quadratic through slabs of 1, 2, 4 and 8 columns taken to zero width: 0.5 and 0.9 %** (fuel/fuel: 0.4 and 1.0 %). That estimator is now the one in E1 and E2. With it the core-tallied case (E1) is **-2,590 pcm (finite differences) and -3,220 (SANM)**. **Retracted below (E7):** I first called this the oracle and the floor of the method; it is not, because the factors are node-face flux over node-*average* flux, which is the standard definition only for a flat flux. The face-flux estimate itself (continuity under 1 %) stands.
- **Wrapper rules found (these go into P1):** (1) openndm's lattice row 0 is its lowest-y side while OpenMC's is the top, so a node's openndm `-y` face is the physical `+y` face, and factors must be handed over with the y faces swapped (not swapping gave +21,000 pcm); (2) factors belong to a composition, not to a position, so a node whose faces meet different neighbours needs its own composition: one wrapper universe per position (a cell filled with the assembly's universe) works and tallies fine; (3) factors on the faces next to the vacuum matter (removing them moves k by about 6k pcm); (4) with subdivision (more than one node per assembly) the factors are applied to every sub-node face and k is wrong by 9 to 24k pcm, so factors are used with one node per assembly only; (5) the `openmc` executable and the `openndm` venv both have to be on PATH, venv first.
- **Reflector constants that see the checkerboard, and corner constants (E4 and E5, `nodal-p2/e4_checkerboard.py`, `e5_swap_pieces.py`, K = 80).** Reflector constants and fuel/reflector factors from strips with the checkerboard behind the reflector ([A B A | R], [B A B | R]) instead of one fuel assembly: two-step k goes from +2,514/+1,980 to **+2,046/+1,542** pcm. Fuel constants from a 2 x 2 color set instead of single-assembly infinite lattices: +2,085/+1,573 (no change). The reflector's own constants hardly move (D 1.126 to 1.110 fast; the edge node's constants match the core run's to under 1 %). Corner reflector nodes with the core run's own constants and factors instead of the edge node's: **25 pcm or less**, so corner-specific constants are not needed on this core.
- **Where the rest of the gap to the core run comes from (E5, pieces swapped, nodal k minus OpenMC k, fdm/SANM):** oracle -2,586/-3,224; core constants with strip factors -634/-1,052; strip constants with core factors +263/-430; both from strips +2,046/+1,542. - **Retraction and what replaces it (E7 and the assembly-power comparison, `nodal-p2/e7_thick_reflector.py`; E5 and E6 also print power).** The "oracle" rows above (core-tallied constants and factors) are not an oracle, so the "floor of the method" wording is withdrawn. Evidence: (1) **assembly power** (fuel nodes, normalised to their mean, against OpenMC's kappa-fission per assembly, statistical error 0.6 %): with the core-tallied factors the rms error is **17 to 23 %** (maximum 35 to 45 %) on the zoned core at one, two and three reflector layers (E6, E7; the 8 x 8 checkerboard's power numbers of E5 are an orientation error, see E11b below), while k is -0.4k, then -0.04k pcm at two and three layers (-1.4k to -3.2k at one): k matches and the power shape is wrong. (2) With **no factors at all**, the SANM power error at two layers is **1.5 % rms (3.5 % max)** and k is +5.1k. (3) Putting the core-tallied factors on **one class of faces at a time** (two layers, SANM, k error / power rms): none +5,135 / 1.5 %; all faces -456 / 20.7 %; fuel/reflector only +4,591 / 9.1 %; vacuum only +4,156 / 4.4 %; fuel/reflector and vacuum +3,478 / 4.7 %; all but fuel/fuel +1,174 / 4.6 %; **fuel/fuel only +5,269 / 20.9 %**: factors on the fuel/fuel faces leave k alone and ruin the power shape. (4) The nodal flux falls off toward the core edge more steeply than OpenMC's (middle row, relative to the centre: fast 0.35 in the reflector node, 0.73 and 0.89 in the next two).
- **My reading of that (E8 below tests it):** a factor defined as (heterogeneous face flux) / (node-average flux) is the standard discontinuity factor only when the homogeneous flux is flat, as in an infinite lattice or a zero-current assembly. In a core the homogeneous nodal solution already has a gradient across each node, so dividing by the average puts the tilt in twice; the right denominator is the homogeneous solution's own flux at the face. That fits (3): the fuel/fuel factors are almost pure tilt and do damage, while the infinite-lattice factors (flat flux) used by the two-step recipe on those faces are harmless. It means the E1 to E7 core-tallied rows are a flawed reference, and that the fuel/reflector and vacuum factors, which do carry real discontinuity, may still be contaminated by tilt. The test is generalised equivalence theory; it was run (E8, below).
- **Equivalence-theory factors tested (E8, `nodal-p2/e8_equivalence.py`, outputs in `e8_output_K80.txt`; the 9 x 9 zoned core with 1 and 2 reflector layers).** The factor of a face is the true face flux over the face flux of the homogeneous solution in the node, taken as the parabola with the Monte Carlo node-average flux and the Monte Carlo net currents on the node's two faces (Fick's law with the node's own D; currents from a surface-current tally on the node mesh). - **A current-preserving D (E9, `nodal-p2/e9a_dump.py` and `e9_current_d.py`, outputs in `e9_output.txt`, the Monte Carlo data of three cores in `nodal-p2/data/`).** A scale on D per kind of node (A, B, reflector) and per group is fitted by non-linear least squares so that Fick's law (the finite-difference harmonic coupling) reproduces the tallied net current across every shared face between two nodes (vacuum faces left out). The fast correction transfers: scales fitted on the 11 x 11 core and applied to the 9 x 9 core give k within about 200 pcm and power within 0.5 % of the core's own fit.

- **Where the fast D shortfall comes from (E10, `nodal-p2/e10_d_source.py`, `e10_output.txt`, `e10_output_solve.txt`).** OpenMC's `transport` cross-section is sigma_tr = (<sigma_t phi> - <sigma_s1 phi>) / <phi>, flux-weighted over the whole group, and openndm's D is 1/(3 sigma_tr): the inverse of an average. The group D that follows from the energy-dependent equation is the flux average of D(E) = 1/(3 sigma_tr(E)), which is never smaller (Jensen), and a group that spans seven decades with resonance dips makes the difference large. Measured on the 9 x 9 zoned core with a 300-group transport tally collapsed both ways: the library's D matches 1/(3 <sigma_tr>) of the fine data to 0.5 % or better (the collapse check is 1.000 on every kind of node on three cores), and **the flux-averaged D is 1.232 to 1.238 times it for the fuel in the fast group, 1.32 to 1.35 for the reflector, and 1.17 to 1.22 in the thermal group** (identical on the three cores to within 0.03). The fuel value is the 1.24 to 1.30 the current fit found; the reflector's 1.52 to 1.59 is only partly explained (1.32 to 1.35); the thermal group was not fittable from the currents but has the same kind of gap (about 1.2). **It does not need hundreds of groups:** collapsing through m intermediate groups per coarse group gives, for the fast group of the interior B node, 1.057 (m = 2), 1.145 (4), 1.194 (8), 1.211 (16), 1.227 (32), 1.233 (60), 1.238 (240); 16 per coarse group already gets D within 2 % of the fine-group value (1.211 against 1.238), which is 89 % of the 24 % correction; 60 per coarse group gets 98 % of the correction (1.233).

- **The flux-averaged D through the normal library path (E12, `nodal-p2/e12_library_path.py`, `e12_output.txt`).** OpenMC 0.15.3 already averages D the right way when a library is condensed: `DiffusionCoefficient.get_condensed_xs` forms D = 1/(3 sigma_tr) per fine group, multiplies by the fine flux, sums and divides by the coarse flux. What the old path lacked was the fine groups: a 2-group library can only give 1/(3 <sigma_tr>) whichever type it carries. So **the path is: tally the library in an intermediate structure (types: absorption, transport, diffusion-coefficient, nu-fission, kappa-fission, chi, inverse-velocity, the consistent scattering matrices), condense it to `[0, 0.625 eV, 20 MeV]` with `Library.get_condensed_library`, and let openndm read D from the `diffusion-coefficient` type (its default preference).** Measured on all three cores, same seeds as E9 to E11, with no hand-made D: the condensed D over the 2-group D, fast, is 1.232 / 1.227 / 1.313 (A / B / reflector) from CASMO-25 up, and the 120-group value of E10 over it 0.996 (so within 0.4 %); CASMO-8 and CASMO-16 get only 1.18 / 1.18 / 1.25 (95 % of it). Nodal solve of the condensed library, SANM, nodal k minus OpenMC k / assembly power rms (max): **CASMO-25: +368 pcm / 2.1 % (5.7) on the 9 x 9 zoned core, +1,072 / 3.5 % (8.7) on the 11 x 11, +314 / 2.6 % (6.3) on the checkerboard** (E10's hand-injected D gave +263, +997, +211: within about 100 pcm); the old 2-group library +4,908, +5,135, +5,340 pcm; CASMO-16 +1,262 to +1,918 pcm (not enough), CASMO-40, CASMO-70, MPACT-51 and MPACT-69 the same as CASMO-25 to within 20 pcm. **Cost:** adding a CASMO-25 or CASMO-40 library to the 2-group one raised the CPU time of the 9 x 9 transport run from 306 s to 364 s (+19 %), MPACT-69 to 373 s (+22 %); condensing 81 domains takes 1 to 1.5 s (2.6 s for SCALE-252, D types only).
- **What the wrapper (P1) should do, from that:** (1) build the intermediate library in **CASMO-25 or CASMO-40** (a structure whose edges include 0.625 eV and whose outer edges equal the coarse structure's: the CASMO and MPACT structures do; XMAS-172, SCALE-44, VITAMIN-J-175 and others start at 1e-5 eV and need the coarse structure to start there too); (2) condense with `get_condensed_library` to the 2-group structure; (3) call `from_mgxs_library` on the condensed library with `d_tolerance` raised: its check compares the diffusion-coefficient D with the transport one and warns when they differ, and they now legitimately differ by 20 to 30 %; (4) say in the provenance that D is the flux average over the intermediate structure (name and number of groups), because a library built the old way is not equivalent; (5) never build the 2-group library directly for a nodal solve. **Not shown:** one seed and three small cores of one material set; the statistical noise of fine-group sigma_tr for small domains (pin-level) is not studied (E10's flux average over 300 groups was stable for an assembly-sized domain); the reflector's and the thermal group's remaining gap (E10: the flux average is 1.17 to 1.22 in the thermal group and the current there is not diffusive at the reflector).
- **The two-step inputs through the library path (E13, `nodal-p2/e13_two_step_library.py`, `e13_output.txt`).** Every piece is a small run tallied in CASMO-25 (all types) and condensed to two groups: an infinite lattice of A and of B, and fuel-plus-reflector strips (the zoned cores: [B B A | R]; the checkerboard: [B A B | R] and [A B A | R], the reflector taken as their mean); five runs of about 40 s each (205 s for the lot with the solves). The core is assembled by kind from those pieces alone (no number from the core run) and solved with no discontinuity factors. Nodal k minus OpenMC k, SANM (assembly power rms, max): with the fuel constants from the **infinite lattices** +2,260 pcm (1.1 %, 2.6) on the 9 x 9 zoned core, +2,728 (1.3 %, 3.9) on the 11 x 11, +2,720 (1.0 %, 3.0) on the checkerboard; with the fuel constants from the **strips' fuel nodes**, which leak toward the reflector and so have a harder spectrum, **+1,107 (1.8 %, 4.2), +1,716 (2.7 %, 5.7), +1,588 (0.9 %, 1.9)**. For comparison the core run's own constants by kind with the flux-averaged D give +185, +702, +381 pcm and 2.2, 3.5, 1.5 %, and the old 2-group library +4,908, +5,135, +5,340 pcm. The finite-difference kernel, same inputs, gives +365, +743, +388 pcm for the strip fuel (it is 0.7k to 1.2k lower than SANM on these cores throughout; the SANM numbers are the ones quoted elsewhere here).
- **Reading E13 honestly:** (1) with small runs only, k is **+1.1k to +1.7k** against +4.9k to +5.3k before the D fix, and **no number from the core run is used**; the remaining +0.9k to +1.2k over what the core's own constants give is, most likely, the fuel constants' spectrum (an infinite lattice, or a strip's fuel node, is softer than fuel inside the leaking core: E5 found fast absorption and nu-fission a few percent off); that reading is not tested here. (2) **Assembly power does not discriminate:** it is 0.9 to 2.7 % rms in every variant, and on the zoned cores the **old** D has the lowest power error (0.7 and 1.5 % against 2.2 and 3.6 % with the right D and the core run's own constants), because its too-small D and the missing factors err in opposite directions in the shape. k is where the D fix shows. (3) The pieces are chosen per core layout (the strip behind the outer fuel ring, the checkerboard strips); for the 11 x 11 core the second reflector layer simply reuses the first layer's constants, and the two-layer core is +1,716 against +1,107 for the one-layer one. (4) One seed; no factors were used (E10 found them second order once D is right, but equivalence factors were not retried with piece-made data).
- **What stands:** the wrapper rules above; the face-flux extrapolation (continuity under 1 %); no factors gives a good power shape (1.5 % rms at two layers, 3.5 % max) and k +5k, so factors are needed for k and the current ones damage the shape; the thick reflector removes most of the k error of the core-tallied case (a boundary effect). **What does not stand:** any statement of the form "the method's floor is -1.4k to -3.2k pcm", and the reading that the two-step errors "partly cancel".

- **Not done:** the pass line (the user's), leakage-corrected fuel constants (critical-spectrum or buckling correction) and position-dependent fuel/fuel factors, a second core, 3D, rods, boron.

**P1: wrap the solver (2 days).** A small module that takes the library, the lattice map and pitch, runs openndm, and returns k, a power map and (optional) critical boron.
Set `OMP_NUM_THREADS` explicitly (the deep dive saw it stall at 16 threads, fine at 1 to 8). Pin one openndm version. Test against openndm's own published numbers
(IAEA-2D SANM +21.5 pcm from 1.02959, BIBLIS-2D) before anything of ours: if the wrapper cannot reproduce them, stop.

**P2: the comparison against OpenMC (the C-4 check; 3 to 4 days).** The same small core run both ways: OpenMC k and a lattice mesh power map against the nodal ones.
Report the k difference in pcm and the power-map differences per assembly. Proposed pass line (to be decided by the user after seeing the first numbers, not before):
agreement within a stated number of pcm and a stated percent in assembly power, with the uncertainty of the OpenMC side included. A failing case is kept as a test.

**P3: the tab (3 to 4 days).** Core tab with the lattice map, group structure choice, "Solve", the nodal k and power map beside OpenMC's k, and the P2 note.
Absent package: the tab is not shown, and the operation says "needs the nodal package" with a setup route (SEED's rule: a missing capability blocks that operation only).

**P4: package manifest (1 to 2 days).** Follows SEED's component manifest format (`seed.component-manifest/0.1`, SEED branch `claude/w2-runtime-contract`,
`docs/runtime-contract.md` and `schema/component-manifest.schema.json`; the SEED agent's note is in `messages/openmc.md`, 2026-10-07). One file, `seed.components.json`,
in this repo, with a component of kind `addon`:
- `id` `nodal-core`, our own semantic version, `title`, `description`; `platforms` limited to what openndm's wheel really supports (not yet checked: Windows via WSL x64 is the
  tested case; macOS arm64 only if a wheel or a build is confirmed);
- `appVersions.min` the Studio version that has the Core tab (P3);
- `dependsOn` the app's core runtime component (its id comes from Studio's own core manifest, to be written with the CAD add-on; not invented here) with a minimum version;
- `capabilities` `group-constants` and `nodal-solve`: the names SEED's note gives as examples, so a Studio operation can refuse with a message naming the missing component;
- `artifacts` the pinned openndm wheel (https URL, sha256, download and expanded sizes, archive type), and our wrapper if shipped separately;
- `license` `spdx: MIT`, with the notices file hash (openndm's MIT notice goes in the package's third-party notices).
SEED pins the manifest hash in its own catalog; a project or agent never supplies a manifest or an install command. Studio keeps owning its capability checks. Models, results and
custom materials stay out of the component folder (removing the add-on must not touch them). The install root, the "only a human presses Add" rule and the trust source are
**undecided by the user**: do not depend on them. Provenance records the installed component versions on every nodal result. Fake-artifact tests first. The manifest for the CAD add-on
comes first (the plan's first case), and the core runtime component's id and version come with it.

**P5: RAFT handoff (1 day).** A result file: nodal k, power map, critical boron, rod worth, with the full provenance and the P2 comparison. RAFT reads that file and nothing else.
The BEAVRS reference data (boron letdown, HZP states) stays RAFT's side; `virtual-reactor/validation/m8_beavrs_hzp.py` already compares against it.

## How to prove it right

1. openndm's own benchmark numbers reproduced through our wrapper (P1).
2. OpenMC vs nodal on a small core, per the P2 comparison, kept as tests; each kept as a regression number.
3. Break tests: scramble the lattice map ordering, swap the group order, drop an assembly's domain; each must make a check fail (the library and the map must share one domain ordering).
4. Removing the package: Studio launches, core runs work, the tab is gone, saved projects still open (SEED plan 11 acceptance).
5. Provenance names the openndm and package versions on every nodal result.

## Risks

- **Library mismatch:** the domain ordering of the MGXS library and the lattice map must agree (openndm has a helper for it; use it, test it).
- **Accuracy on a real core:** nodal diffusion has stated limits (rod cusping, no pin-power reconstruction). The tab says what it cannot do.
- **Thread stall and maintenance:** pre-1.0, one main author; pin a commit, record the version, set threads explicitly.
- **Group constants cost:** generating them needs an OpenMC run per assembly type; on a full core this is minutes to hours, not seconds. P0 measures it.
- **Scope creep:** depletion, pin power, transients stay out until P2 passes.

## Not in this plan

Depletion; the pin-power table and IFP kinetics (separate items from the investigation report); GPU or Metal engines; any claim of accuracy for non-PWR cores.

## Decisions for the user

1. Studio owns the package; RAFT is the first consumer, SEED packages and installs it. (Proposed.)
2. The pass line in P2: decided after the first comparison numbers, by the user.
3. Start with P0 now. The manifest format is now written (SEED W2, pending its merge to SEED main), so only the open install-root and trust questions remain with the user. Recommended: start P0; write the manifest after the CAD add-on's manifest exists.
