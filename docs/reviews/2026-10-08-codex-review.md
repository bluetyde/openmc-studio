# Codex review of 2026-10-08 (specification-gap and silent-failure auditors)

Scope: everything merged since `5d37195` that is not a plan or a test: depletion D1 to D4 (record writer, id, server hook, several regions), the shared pre-run check, the material assistant (Python and its JavaScript port), the pin-power view, and the agy modules wired into the Results page. Two auditors, each given about half of the diff (the whole diff was over the tool's limit): a specification-gap auditor on the record writer, the pre-run check, the material helper and the page, and a silent-failure hunter on the server hook, the run checks, the report and the pin-power code. Eleven findings. Each was checked against the code before anything was changed; all eleven were real. Ten are fixed on branch `claude/codex-review-fixes`, one is open.

| # | Finding | Severity (Codex) | Disposition |
|---|---|---|---|
| 1 | `_depletion_record` could raise before `run.finish`: a read-only `provenance.json` left a finished run "running" for ever and blocked the next run. | High | Fixed: the run always ends (`try/finally`); a failing record step is logged in the run's output. Test: `test_codex_review_fixes.py`. |
| 2 | The inventory chart divided by the heavy metal rebuilt from the *listed* nuclides, so a thorium or U-233 fuel showed its starting U-235 as 1 instead of 0.01. | High | Fixed: the record now carries `provenance.heavy_metal_atoms_start` (every nuclide with Z of 90 or more, per region) and the chart uses it; a record without it falls back to the old way. FEED reads provenance as free-form, so its reader is not affected; Studio's two record fixtures were rebuilt (new ids). |
| 3 | `prerun_gate` turned any exception in the check into approval (a project with `particles=0` and a list for a material id ran). | Medium | Fixed: a check that cannot read a project refuses it, with the reason (`prerun-check-failed`). |
| 4 | The pin map was offered for every mesh score and called "Pin power": a flux mesh gave a "relative power" peak. | Medium | Fixed: only energy-production scores (kappa-fission, fission, heating, heating-local, fission-q-prompt, fission-q-recoverable) are "Pin power"; any other score is a "Pin map" with a "not power" note, and the button says "Pin map…". |
| 5 | The symmetry check skipped pin groups with zero uncertainty, so strongly different pins with sigma 0 passed as "within noise". | Medium | Fixed: a spread with no uncertainty is not a pass (`max_z` is null, `within_noise` false); the page says so. |
| 6 | An unusable provenance record made the run report throw away the results and findings it was given (lost-particle warnings vanished). | Medium | Fixed: they are kept; the report is marked "record unusable". |
| 7 | Applying UO2 or heavy water from engineering inputs kept the old material's thermal scattering table (c_H_in_H2O on UO2). | Medium | Fixed: the table is cleared; light water gets `c_H_in_H2O`; heavy water is told to choose. The earlier test that asserted the old table stayed was wrong and was changed. |
| 8 | A stopped or failed burn's incomplete record could not be opened in the UI (Results enabled only for "done"). | Medium | Fixed: Results is enabled for every run that is not running; a stopped or failed burn loads its results when it ends; Open model loads them for a burn. This also makes resume (planned) reachable. |
| 9 | A single region's power shares were not checked to sum to 1 (only several regions were), so a direct `build()` caller could halve a burnup in an id-stamped record. | Medium | Fixed: shares are checked for every region count. |
| 10 | A fertile region (a U-238 blanket that has bred nothing the chain keeps) had no U-233/U-235/Pu-239/Pu-241, so the fission-Q check aborted the whole record. | Medium | Fixed: when none of the four is there, any heavy nuclide left with a fission reaction in the chain gives the Q; the record is still refused only when none exists. |
| 11 | Python's pre-run check lacks the "burnable material in a part inside a lattice" refusal that the page has, so `/api/run` accepts such a model. | Medium | **Open (known).** Listed since the shared check was written (TODO: "Not covered yet"). Needs the page's `latticePlan` ported so the two refuse the same models; the risk of a stricter Python check is a refusal the page does not give. Until then the model fails later with a zero volume, not silently. |

Verification of the fixes: new tests in `test/test_codex_review_fixes.py` (10), the three page suites and the writer, record and report suites; a mutation run over the changed code (16 mutants: 13 killed on the first run; one survivor was an identity replacement that changed nothing; the other two, in the page's end-of-run and Open model handlers, were given tests and are now killed). Codex's own run could not run the OpenMC-dependent tests (OpenMC was not available to it); the fixes were tested here in WSL.

What the review did not cover: `static/index.html` outside the depletion, pin-power and material helper parts, the exporter, CAD import, and the headless runner beyond `check_project`.
